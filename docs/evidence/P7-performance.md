## Frozen reference target

`blendlib-showcase` now contains the deterministic contract
`blendlib-showcase-p7-reference-scene-v1`:

| Path | Required visible instances | Geometry per instance | Total triangles |
|---|---:|---:|---:|
| rigid | 100 | 10,000 triangles | 1,000,000 |

`test-assets/p7-performance/reference-scene.json`.

## Real isolated-client attempt — invalid, not a result

On 2026-07-29, before ADR-017 replaced the original spatial layout/camera contract, the isolated
`run/p7-benchmark` client loaded the generated resource pack, reported generation 2 with six
loaded models and zero reload diagnostics, and the explicit local command created exactly 100
rigid plus 25 skinned hosts. The controller then completed its 600-frame warm-up and correctly
refused to summarize the first measured frame because the actual submit counters were
`rigid=0, skinned=10`, rather than the frozen `100/25` target. It wrote only:

`D:\BlendLib\blendlib-showcase\run\p7-benchmark\benchmark-results\p7-runtime-invalid-1785311742510.json`

with `status: INVALID_OR_INCOMPLETE` and `gate: WAITING`. No timing, allocation, FPS, or visual
claim may be inferred from that file. The same run later exposed a separate real extraction crash
for `blendlib_showcase:p7_benchmark_skinned`:

`Skin normal transform requires an invertible joint matrix`

The crash report is retained only in the isolated run directory at
`D:\BlendLib\blendlib-showcase\run\p7-benchmark\crash-reports\crash-2026-07-29_15.57.25-client.txt`.
The corrective work is constrained to preserving the exact 100/25, 1,500,000-triangle, 64-joint,
600/1,800-frame target; it must not hide partial submissions, relax normal-matrix validation, or
turn this invalid run into a Gate result.

The generated P7 mesh/joint nodes have since been repaired to declare explicit identity TRS. An
independent focused strict loader-to-pose-to-CPU-skinning probe at animation times 0, 0.5, and
1.0 seconds produced invertible normal matrices and finite outputs. No subsequent isolated client
run has been used to assert a performance result, and no post-repair FPS, allocation, visual, or
performance result is claimed.

## Still required for the P7 Gate

No JFR, profiler capture, real visual inspection, shaderpack/visual Iris-Sodium smoke, 20-reload
leak result, or 60-FPS result is claimed here. The separate no-shader Iris/Sodium startup smoke
in `P7-implementation.md` establishes only isolated startup/no-fatal-render-error evidence and
does not change this performance status. ADR-017 and ADR-020 are accepted, but
a fresh isolated real-client run is still required before a valid reference
result can be claimed. It must:

1. Install the generated resource-pack bundle and benchmark-only entity wiring in an isolated
   client directory, never an official server or formal world.
2. Verify every one of the 125 target instances is visible and submitted at the owner-resolved
   reproducible camera contract before sampling.
3. Warm up for 600 frames, capture 1,800 frames with JFR or a profiler, and feed genuine timing,
   live allocation, and cache observations to `P7ClientMeasurementHarness`.
4. Preserve p50/p95 frame time, animation preparation, submit CPU, allocation, cache/handle
   observations, environment details, and evidence screenshots/logs.
5. Evaluate the 60 FPS requirement and all P7 compatibility/leak Gates separately; no unit test
   or generated artifact can replace that evidence.
