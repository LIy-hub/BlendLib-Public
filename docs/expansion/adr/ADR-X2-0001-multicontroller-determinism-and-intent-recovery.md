# ADR-X2-0001: multi-controller determinism and scope-bound intent recovery

状态：Proposed/Experimental implementation candidate

## Context

现有 v1 动画接口、同步 payload、client lifecycle、reload 与 render/extract 链路均是已存在的边界。X2 需要试验多 controller、layer mask、override/additive、crossfade、`next` 和 late/reconnect intent recovery，但不能通过改变这些 v1 surface 或在热路径发现资源来获得能力。

## Decision

X2 在新的 internal `animation.v2` namespace 使用以下模型：

1. `AnimationV2InstancePlan` 是配置期验证完毕的不可变输入。bone name 仅用于构建期；执行期只读取已解析 index 和 immutable clips。
2. 运行时以 controller priority ascending/canonical id ascending、再以 layer priority ascending/canonical id ascending 得到固定顺序。static no-op diagnostic 也只在该 canonical 顺序完成后收集，因此进入 64 条有界 collector 的集合与 truncation marker 不依赖 caller 输入顺序。外部 command 在唯一 owner 的 snapshot boundary 先捕获完整有界 ingress/backlog，再按完整语义排序并以 `(controller id, sequence)` 建组：相同值去重，任何字段不同的同组值整组拒绝且写入 sequence watermark，arrival order 不参与结果。每帧最多处理 128 个完整组；组不能被预算切开，未选组留在固定 owner backlog。后来收到 equal/newer 的冲突或非法组会撤销既有 state 到初始中立值，不能让先到赢家永久存活。
3. 对每根 bone，最高 controller priority 的 override 贡献获胜；同 priority quaternion 的归一化混合使用一个共享 reference：rest 权重非零时用规范化 rest，否则用 canonical controller/layer 顺序首个有效 winner。其余 quaternion 按 reference dot 对齐，dot 接近零使用 canonical tie-break，最终结果再规范化并 canonicalize。additive 在 override 结果后执行。任何 non-zero exclusive 与任一其他 non-zero override/additive 冲突；overlap、controller competition、低 priority suppression 和 no-op 都保留结构化 diagnostic，而不是静默选择。
4. 每个 controller 独立运行 `LOOP`、`ONCE`、`HOLD` 和 `next`。`HOLD` 推进到末端再保持；中断 crossfade 冻结已混合 source presentation。`next` cycle 与每次推进的 automatic transition 数有 hard bound。时间、effective speed、weight、mask、clip、transition、diagnostic、256 条 callback queue、256 条 synchronous frame batch、至多 512 条 core captured raw snapshot、256 条 deferred frame buffer 与每帧 128 个完整组均有有限上限。
5. common 的 `AnimationIntent` 只包含 scope、controller id、animation key、start tick、sequence、speed 和 intent mode。core state/plan/command/rejection/observer 以及 common intent 的 controller/animation `BlendResourceId` 与 `BlendAnimationKey` 在进入语义运行时前均限定为至多 256 UTF-16 code units。每条 intent 必须先完全匹配入站 `(session, world, instance, generation)` scope，才可进入 `(controller id, sequence)` group、plan validation、watermark 或 retention；错误 scope 只能 `SCOPE_REJECTED`，不能与 active intent 建组、触发 retire 或被 client 转换成 core sequence rejection，且不消耗 active 完整组预算。`AnimationIntentReconciler` 在 retention 前检查 frozen controller whitelist。watermark 比较发生在 conflict 与 plan-validation 的所有破坏性路径之前：`sequence < watermark` 一律 `STALE_DROPPED` 且不改变 accepted/persistent；equal/newer conflict 或 plan rejection 才推进/保留 watermark 并 retire。只有相同 session/world/typed-instance 的 generation-only rebind 能保留语义值，并须按 replacement plan 再验证。persistent replay 不跨 scope。
6. client X2 runtime 允许 callback 线程向 bounded queue offer immutable intent，但仅一个 owner 安装、推进、replay 或 teardown。owner 先推进旧状态，后在 frame boundary 应用 due absolute command；它发布 immutable snapshots，且不注册 packet、reload、lifecycle 或 renderer。
7. owner 在每次 advance 的 immutable snapshot 中附带最小 observer-only automatic traversal：每 controller 最多 128 个真实 forward segment；segment occurrence 严格单调，只有实际 `LOOP` wrap 才推进 loop epoch，automatic `next` entry/leftover time 也被记录。playhead/segment 边界严格按实际 representable double：严格小于 duration 不跨越，exact duration 恰跨一次，`nextUp(duration)` 只把真实 residual 带入下一 occurrence；不得用 `EPSILON` snap。LOOP terminal 仍由 `% duration` 得到；completed-wrap count 对 exact binary64 significand/exponent 求 floor，普通情况走 primitive 无分配除法，极端可装入 long 情况才走固定最多 116 位的 long division，不能把 quotient round 回 double。可装入非负 `long` 的 identity 必须精确，`>Long.MAX_VALUE` 和累计 counter overflow 均 fail closed，不能 saturation 或伪造 provenance。当前 snapshot 还冻结 owner-local rolling continuation：每个 non-empty publication 带 exact source revision 和前后 `(timeline,time,revision range,loopEpoch,occurrence)` anchor，连续 no-movement revision 只扩展 anchor range。X3 必须用自己的 committed observation 的全部字段定位 exact anchor，再消费之后连续的 owner publication；因此 budget 内 skipped publication 可精确补发 crossing。找不到 anchor、最旧 anchor 被 128 real-segment bound 剪掉、truncation、command 或 sequence rejection discontinuity 都不能由 X3 猜测/只比较 latest segment，必须 explicit diagnostic + nonpublishable fail closed。超限清空 partial trace 并给 `OBSERVER_TRAVERSAL_TRUNCATED`，而不是无界遍历或猜测 provenance。旧 public 四参数 snapshot 构造器保留且产生 empty trace；observer 类型不公开 mutable constructor/mutator，任何 X3 consumer 仍须同时验证 exact owner runtime 的 `latestSnapshot()` object identity。
8. r8 的 previous preflight wording 只适用于其 exact-long/counter domain，不能作为 whole-frame atomicity 结论。independent r8 review 以 late revision、legal finite pose intermediate 与最大 UTF-16 automatic-next diagnostic 判定 **FAIL（0 Critical / 0 High / 3 Medium / 1 Low）**。r9 candidate 改为在 next revision check 后把 live controller/backlog 复制到 owner-only `FrameStage`，在该 stage 完成完整 prospective frame 的 controller advance、captured ingress、rejection、command、diagnostic 与 pose，生成 complete immutable snapshot 并 prepare live commit capacity，随后才消费 captured FIFO prefix 并提交 live controller/backlog、revision 与 `latestSnapshot()`。stage 可发生 disposable mutation；只保证 pre-commit failure 不改变 live/observable owner state。`NEXT_CYCLE` diagnostic detail 另行限制为 256 UTF-16 code units（包括 prefix/ellipsis）并避免 surrogate split；它不是 semantic identifier limit 的放宽。`AnimationV2TransformScratch` 对 additive/interpolation 使用 double intermediates，最终 float publication 仍须 finite，scale 仍须 positive。formal r9 review 为 **FAIL（0 Critical / 0 High / 1 Medium / 2 Low）**。
9. r10 是对该内部 runtime 的窄域修复而非新 API，但其 fresh review 实际为 **FAIL（0 Critical / 0 High / 1 Medium / 1 Low）**。Medium 有两个 ADDITIVE 根因：same-priority/ADDITIVE effective layer×mask 在 Runtime 中先以 float 相乘，使合法 dyadic subnormal weight 在进入 double accumulator 前归零；Scratch 又在 additive translation/scale 和 relative quaternion delta/Hamilton 链中提前收窄 float。Low 是 pending generation 的有限模 equality 在精确 `2^64` rejection 后 ABA，capture 后 suffix diagnostic 可能被清除。r11 candidate 因此令所有 ADDITIVE effective weight、translation、scale、relative delta、normalization、slerp 与 second Hamilton 在每个乘法/乘加前为 primitive `double`，仅最终 finite/positive checked publication 回到 float；不可表示仍 fail closed。overflow 使用只在 rejected offer 创建的 fresh private ticket，producer `AtomicReference` set 与 owner captured-ticket identity CAS 是线性化点，故不依赖任何有限 generation。r11 final-hash audit 的 **NON-VERDICT — NO-BLOCKER（0C/0H/0M/0L）** 不是 review PASS；formal r11 review 为 **FAIL（0 Critical / 0 High / 1 Medium / 1 Low）**，formal r12 review 为 **FAIL（0 Critical / 0 High / 1 Medium / 1 Low）**，fresh independent r13 review 为 **PENDING**。

## Alternatives rejected

- 扩展 v1 `SyncedAnimationState` 或现有 payload：会把 Experimental controller/scope 语义混入稳定 wire contract。
- 让 renderer/network callback 直接改 playhead：会让线程、arrival order、重连和生命周期结果不可复现。
- 根据注册顺序或最后写入 winner：会导致同一输入集随 callback timing 改变。
- 在 `advance`/sample 中加载资源、解析 GLB/JSON、查 registry 或 discovery provider：破坏冻结 generation 与热路径预算。
- 将 X2 直接公开为新的 stable API：尚无 API compatibility、payload、adapter 或实际 visual evidence。

## Consequences

X2 的 core/common/client 单元与 source-boundary 测试可以证明内部 deterministic/runtime contract；其中 hot-path structural probe 可证明没有 layer full-pose/list temporary construction，但不能替代硬件 allocation 或 CPU benchmark。`r9-13-pre-doc-build-release` 的 `116 suites / 837 tests / 0 failures / 0 errors / 0 skipped` 与 SHA256SUMS `17/17` verification 是历史文档冻结前 implementation-side baseline，不能推导真实网络、reload、platform host、variant/material、visual、Iris/Sodium 或性能正确性。r9 `#10b` 的实际 `39/276`、r10 replay `39/280` 与正确 task-bound `8/51` 必须诚实区分。r13 的 docs-bound release 尚未运行；最终 binding 仅由这轮九份文档冻结 hash 后唯一一次 `buildRelease --rerun-tasks` 与独立 SHA 验证决定，artifact 缺失或不匹配即 binding 未证明；formal r9 为 **FAIL（0 Critical / 0 High / 1 Medium / 2 Low）**，r10 fresh review 为 **FAIL（0 Critical / 0 High / 1 Medium / 1 Low）**，formal r11 为 **FAIL（0 Critical / 0 High / 1 Medium / 1 Low）**，formal r12 为 **FAIL（0 Critical / 0 High / 1 Medium / 1 Low）**，fresh independent r13 review 为 **PENDING**。

### r12 formal failure 与 r13 Transform publication note（candidate only）

formal r11 的 Medium 证明 canonical quaternion 可以在 Scratch raw endpoint 后经 public publication projection 改变 bits。formal r12 的 Medium 则是 r12 以 T10 改变 stable public `Transform` value semantics，而未获得 approved source-of-truth/Accepted ADR；此 Proposed ADR 不能自我授权。r13 恢复 stable parent `Transform` 的无条件 `Quaternion.normalized()` publication，故 `0x3F800004` 仍从旧且当前的 `0x3F800000` 发布。两层边界为：Scratch 保留 canonical raw quaternion，fully-public runtime 只暴露 stable normalization projection。q/-q、signed zero、subnormal、permutation 与 current!=rest/override/prior-additive 的 rotation-equivalence、determinism 和 atomicity 均留在测试。r12 Low 的 `9.000002953` 小于精确保守 `9.000003072433528` ULP，且 evidence 未绑定三 hash/artifact；它是历史错误，不是 r13 证明。formal r12 review 为 **FAIL（0 Critical / 0 High / 1 Medium / 1 Low）**；fresh independent r13 review 为 **PENDING**。

本 ADR 不改变 v1 API/SPI、Profile、payload、capability protocol、Fabric target 或 P0--P8 Gate；它不索引或修改既有 ADR/progress ledger。
