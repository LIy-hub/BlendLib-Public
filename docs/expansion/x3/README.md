## 运行时边界

- `ProceduralRigPlan` 在配置期冻结 model key、generation、bone schema、parent slot、socket/surface slot、hooks、attachment 与 `ProceduralVisualEventMarker` catalog。child-model topology 必须从一个 generation-wide complete descriptor-owner map `compile`，再以同一 graph 的完整 plan set `publish`；对 multi-owner 或含 child edge、因而需要 complete publication 的 graph，class-loader-wide 有界 claim 保证同一 generation 只能有一个 active graph identity。缺 owner、foreign graph、split reload、同代第二 graph、容量溢出或 child edge 默认构造都会拒绝。exact same graph 的重复 publish 幂等；旧 graph 必须显式、幂等 `close()`，退役后永不重新激活。无 child edge 的单模型 plan 是 topology-exempt，才可使用安全默认空 graph；名字或资源解析不在 evaluate 热路径发生。
- `ProceduralRigRuntime` 在构造时绑定一个完整、精确的 `ModelInstance`（typed instance、model key、generation）。同 model/generation 的 sibling instance 仍会 `STALE_SCOPE`；generation replacement/rescope 必须新建 runtime。只有完整 X3 snapshot 成功原子提交后 revision watermark 才前进；等值/回退为 `STALE_REVISION`，而失败帧可用同一 exact X2 snapshot 重试，且仍保留上一成功 snapshot。
- 含 visual-event catalog 的 runtime 还必须绑定一个**精确 X2 `AnimationV2InstanceRuntime`**。两参数 legacy 构造器只接受空 marker catalog；非空 catalog 会在构造时立即失败，不能静默退化为空事件。三参数构造器冻结时只读 X2 `plan()` 来验证 controller/state/clip duration；evaluate 时只接受其 `latestSnapshot()` 的同一对象。每个 marker 使用 owner 的精确 `(start,end]` segment 边界：`end` 恰好一次，`nextUp(end)` 只能等真实后续 traversal，duration 也不采用 epsilon 放宽。owner 的 strict `nextDown(duration)` 不得伪造 duration segment、wrap、epoch/occurrence 或 replay identity；exact duration 跨一次，`nextUp(duration)` 只以真实 residual 进入下一 LOOP/automatic-`next` state。r8 将 completed-wrap identity 以 exact binary significand/exponent quotient 计算，只有可装入非负 `long` 的 identity 才可发布；`>Long.MAX_VALUE` 或累计 counter overflow 在 snapshot/revision/provenance 前 fail closed，因此 X3 不会收到饱和或邻近偶数的 epoch/occurrence。terminal 仍由同一 `% duration` remainder 决定。已 armed 的 X3 以已提交 observation 的 timeline/time/revision/loopEpoch/occurrence 在该 exact snapshot 的 rolling continuation 中定位，随后消费所有连续 publication；budget 内 skipped X2 publication 会精确 catch-up，不重不漏。LOOP wrap 和 automatic `next` entry 的每段真实 forward path 带有单调 `loopEpoch`/`occurrence`。若 history 被剪掉、trace truncated、command/sequence rejection discontinuity、terminal facts 不匹配或 exact anchor 不存在，则整个 frame 以 `VISUAL_EVENT_PROVENANCE` fail closed，绝不 `published=true` 后静默丢 crossing。首次 late observer 只 arm latest terminal，不补发旧 history；失败 X3 frame 不提交 observation/replay，same exact snapshot 可重试。发生上述不可连续情形后，未来 integration 必须 retire/recreate 对应 X3 runtime（新 scope 明确 arm latest）才能恢复，不能把失败 frame 当作隐式 re-arm。
- attachment graph 先以全图 raw descriptor visit budget（4096）读取 source，之后才 deduplicate child edge；owner（4096）、unique edge（4096）和 active generation claim（256）仍是彼此独立的限制。有限/无限 iterable 都只能至多读取一个超限 descriptor 后失败，且失败 compile 不会建立 claim。
- `ProceduralFrameInput` 只捕获已发布 X2 evaluation 与有界数据；frame attachment 不可临时注入 `CHILD_MODEL`。raw visual-event list 仅保留为受控的负向输入边界，不能发布事件。runtime 以 scope-local bounded replay fence 抑制已成功发布的真实 marker identity；traversal cursor、replay identity 与 revision watermark 只在完整 frame 的同一最终 commit 点更新，失败不消耗它们。
- 一个 `ProceduralRigRuntime` 只允许其首个 owner thread 调用；跨线程调用抛出 `ProceduralOwnerThreadViolation`，其中携带 `OWNER_THREAD_REJECTED` 结构化 diagnostic。读者只能读取原子发布的深冻结 snapshot。graph retirement 与最终 frame commit 共用线性化点；evaluate 中途退役会以 `ATTACHMENT_GRAPH_RETIRED` fail closed，不提交 snapshot/replay/crossing。
- X3 永不调用 `AnimationV2InstanceRuntime.advance`、enqueue/command/intent mutation、`ClientAnimationV2Runtime.advance` 或任何 X2 callback/reload/render mutation。为了不可伪造 provenance，只有 `ProceduralRigRuntime` 与其 private registry 可以命名 exact X2 runtime，且只读 `plan()` / `latestSnapshot()`；source 与 bytecode test 固定此最小例外。X2 pose 是只读源。
