# Item material appearance (Minecraft 26.3)

## Inspected gap and layered plan

Item extraction currently freezes an animation snapshot or prepared handle but exposes no
per-stack material selector. Entity snapshots already support exact authored slots, immutable
RGB multipliers and visibility; this feature reuses that capture and submission machinery.

1. Add an optional extraction-only item selector using atomically paired binding/configuration
   registration. Preserve the existing binding record, constructors and registration descriptors.
   Repeated binding registration preserves its selector; conflicting selectors are rejected.
2. Capture selection once after animated/static/missing fallback selection, with the exact stack
   object and handle generation. Keep only the immutable render snapshot after extraction.
   Supply an extraction-only captured observer for explicit unknown-slot diagnostics without
   retaining stacks or altering playback, observation, weak identity or LRU behavior.
3. Keep unknown-slot fallback atomic, missing diagnostics authored, authored/whole-model tint,
   alpha, display transform and vanilla lighting intact. No submit-time callback or lookup.
4. Add an opt-in runnable two-wand example using actual authored slots and the same selector
   helper in executable packaged verification. Pin additive public ABI and retain old descriptors.
5. Run focused tests, official 26.3 build/JAR checks and aggregate checks, obtain one critical
   review, repair findings, publish only this stacked branch and observe exact-head CI to terminal.
   Deliver cumulative source, JARs, documentation and evidence through Library.

No textures, alpha controls, emissive, schema/network identities, persistent item IDs, duplicate
render engines or copied geometry. Native graphics acceptance remains deferred. No merge,
tag, release or CurseForge publication.
