# 26.3 bounded standard-entity attachment composition

## Goal and scope

Allow a prepared character snapshot to carry a weapon snapshot that carries an ornament
snapshot, using the existing standard entity attachment API. Capture the entire composition
before submit. This is an additive standard-entity rendering feature, not a new animation,
resource-loading, item/block attachment, or procedural-graph lifecycle API.

Public entry point: `BlendEntityAttachmentComposition.capture(root)`. Its `attachments()`
result is an immutable flat draw list; `diagnostics()` captures composition failures without
requiring submit-time lookups or logging. The standard entity renderer uses the same capture
operation during extraction and retains its result for submit. Custom hosts can reuse this
operation, provided they satisfy the same extraction and culling obligations.

## Immutable inputs and extraction boundary

1. Prepare each model through its existing supported snapshot/animation path. Apply its final
   pose modifiers and material appearance there, and capture final sockets from that same pose.
2. Build children first with `BlendEntityAttachment.at(socket, offset, childSnapshot)` and
   `ModelRenderSnapshot.withAttachments(...)`. A child's socket set belongs to that child, not
   to the character or to an earlier base pose.
3. Capture and validate the bounded graph once during extraction. Preserve deterministic
   parent-before-child traversal and each parent's attachment-list order.
4. Submit the root and captured flat attachments. No resource lookup, socket lookup, controller
   advancement, animation sampling, graph traversal, or entity/world access belongs in submit.

Socket generations must match the snapshots from which they were captured. Generation equality
alone cannot prove socket provenance: consumers must pair sockets with the correct model and
final pose. Animation/runtime lifecycle owners remain responsible for reload and teardown.
The composition helper does not resurrect retired handles or create a second controller cache.

## Transform contract

For character socket placement `P`, weapon offset `Ow`, weapon-local final socket attachment
placement `Q`, and ornament offset `Oo`, the ornament placement is:

```
P × Ow × Q × Oo
```

The weapon's own geometry is submitted under `P × Ow`, followed by its ordinary snapshot root
and asset-unit conversion. `Q` already contains the weapon's own root transform. Multiplying
that root separately before `Q` would apply it twice. The ornament's ordinary snapshot root
and unit conversion are applied once when submitting its geometry.

Use `BlendEntitySocket.attachmentPlacement()`, normally via `BlendEntityAttachment.at(...)`.
Do not substitute model-space or world-space socket coordinates. Attachment placement preserves
inherited pose scale but removes the socket owner's asset-unit conversion from scale. Offsets
are in socket-oriented blocks. Each child retains its own asset-unit conversion. Composition
must preserve rotation, translation, and positive uniform scale, including non-identity roots,
rotated offsets, and differently authored parent/child unit scales.

## Bounds and fail-safe behavior

- Maximum **64 visited attachment occurrences** for a root capture; the separately submitted root is
  not an attachment occurrence. Shared child snapshots mounted twice count twice, including
  their descendants. Invisible and stale entries also consume the budget; traversal stops at a
  stale entry, so its descendants are not visited. The limit is not just a draw count.
- Maximum **eight attachment edges** below the root. A character -> weapon -> ornament chain
  has depth two. Cycles are checked by snapshot identity, not model key. Finite same-model
  attachment chains and repeated immutable snapshot instances are legal. A wide DAG must not evade the
  occurrence budget through repeated references.
- All submitted descendants must use the root's resource generation. A stale child's entire
  subtree is skipped and a diagnostic is captured; unaffected branches remain usable.
- Missing-model diagnostic snapshots retain their visible placeholder and captured diagnostic.
  Composition does not load a replacement model or silently convert missing models into success.
- `RenderVisibility.CULLED` suppresses rendering of that snapshot's subtree. Its same-generation
  descendants are still traversed and validated during capture. Hiding a material slot only
  hides that model's affected geometry; it does not hide separately attached children.
- Each child keeps its own packed light, overlay, tint, appearance selection, and prepared
  geometry. Do not overwrite them with the character's values during flattening.
- Excessive depth/count, malformed topology, and non-representable composed transforms must
  throw `IllegalArgumentException` during capture; no partially captured result is returned.
  Never partially recurse during submit.

Reuse a core topology-validation primitive where its contracts match. Do not instantiate or
activate a `ProceduralAttachmentGraph` merely to validate standard snapshot topology. Its
registration, ownership, generation claims, retirement, and close semantics remain intact.
The shared pure topology validator uses model-key nodes for procedural graphs and
snapshot-identity nodes for entity compositions. It must not expose an alternative path around
those lifecycle checks.

## Culling requirement: conservative root envelope

Vanilla entity culling happens **before extraction** and therefore before attachment capture.
The standard entity path uses the root model's envelope. This feature does **not** compute an
aggregate attachment bound and does not automatically enlarge the vanilla culling box.

Consumers must explicitly provide a conservative root envelope covering every permitted
attachment combination, animation pose, root rotation, scale, and socket offset. An ornament
outside that envelope can disappear with an off-screen character even while the ornament
would otherwise be visible. Capturing a larger child `CullingMetadata` after the character
has been rejected cannot repair this. Choose an intentionally conservative root model envelope
or a supported host culling policy before enabling the composition. Visual attachment bounds
are not authoritative server collision/hit boxes.

## Implementation and verification plan

1. Add the immutable reusable capture and structured diagnostics; share pure topology validation
   with the existing core graph only where contracts are equivalent.
2. Wire capture into standard entity extraction and store the flat result in render state.
   Keep submit snapshot-only and preserve the one-level attachment path's behavior.
3. Verify three levels, siblings, repeated child occurrences, depth eight/nine, count 64/65,
   stale child subtrees, missing-model placeholders, whole-snapshot visibility, material-slot
   visibility, and child lighting/appearance.
4. Verify full transform matrices with non-identity child roots, nonzero/rotated offsets, inherited
   scale, and mixed asset units. Explicitly catch a double application of the weapon root.
5. Retain procedural graph lifecycle regression tests and prove repeated submit does not sample,
   resolve, mutate, or walk attachment topology.
6. Compile the public consumer example against the branch's newly published 26.3 coordinate.
   Report automated checks separately from native in-game visual acceptance.
