# Runnable nested attachments (Minecraft 26.3)

## Scope and sequence

1. Keep the existing opt-in `blendlib_runnable_examples:layered_actor` registration and
   appearance, dynamic animation layers and procedural tip rotation. Replace its single
   marker with a bounded three-level assembly: skinned actor → rigid weapon → skinned ornament.
2. Reuse repository-authored assets. Resolve current-generation handles during extraction,
   prepare the ornament through the entrypoint-owned animation runtime with an independent
   owner identity, and capture the weapon mount from the same prepared root/units.
3. Retire child identities on entity unload and disconnect, omit unavailable optional children
   and sockets safely, and let the existing runtime generation change retire stale bindings.
4. Constrain the authored offsets and scales to a proved conservative root envelope. Automatic
   aggregate attachment culling remains unimplemented; document resource-pack limitations.
5. Exercise the actual shipped example classes and packaged assets headlessly, including
   extraction, composition, independent animation, reload, missing children and lifecycle.
   Build both JARs, verify opt-in isolation, run focused and aggregate tests, and perform one
   independent focused review. Publish only this stacked feature branch and verify exact-head CI.
6. Produce a cumulative source/JAR/evidence bundle for Library delivery.

## Boundaries

No new general library API unless a demonstrated consumer gap makes it necessary. No renderer
submit-time resource lookup, parsing, controller mutation, or topology recomputation. No test-only
reflection in production. Keep normal BlendLib JAR free of example registration/resources.
No merge, tag, release or CurseForge publication. Native graphics acceptance remains deliberately
deferred; headless checks must not be labelled native visual PASS.

## Local verification result

- Official 26.3 `build verifyRuntimeJar verifyRunnableExamples`: passed, 175 JUnit tests
- Actual packaged appearance actor → rigid weapon → cyan CPU-skinned ornament: passed;
  real animated vertices, dynamic layers/procedural final socket, per-material appearance,
  independent ownership, unload/session/disconnect, reload and optional-resource checks
- All-pose authored-geometry bound proof: both descendants fit the existing root cube;
  packaged static marker roots, unit scales, influence radii and configured offsets are checked
- Normal library JAR is byte-identical to the nested-attachment baseline; no new library API
- Root `check --continue`: 1,480 tests, one unchanged Linux symlink diagnostic-message
  assertion failure and one skip; all 685 client and 324 core tests pass
- Focused independent source review: no actionable findings
- Native graphics/frustum-edge acceptance: deliberately deferred, never marked passed

Exact-head remote CI and cumulative artifact evidence accompany the delivery bundle.
