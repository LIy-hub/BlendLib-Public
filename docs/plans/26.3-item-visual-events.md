# Opt-in animated item visual markers (26.3)

## Scope and compatibility

Add an overload of `BlendLibItemAnimations.register` accepting an extraction-thread
presentation handler. Preserve existing registration, constructors, controls, identity,
pose behavior, render submission and exact dependency pins. Handler receives the exact
stack and immutable model/state/generation/descriptor-marker information. No gameplay,
networking, world positions, descriptor-next semantics or per-display identity.

## Layered implementation

1. Preserve the pre-normalization sample interval inside item playback. Controls that
   reposition (play/restart, seek, stop) establish a silent baseline; pause/speed retain
   real advancement. Successful consumption resets interval origin to the sampled pose.
   Failed extraction restores the existing playback checkpoint and invalidates events.
2. Read immutable prepared descriptor markers through an additive runtime query. Use an
   item-specific cursor, not the synchronized descriptor controller: explicit LOOP, ONCE
   and HOLD govern crossings independently of descriptor loop, speed and next settings.
3. On successful extraction consume the interval before callback delivery. Initial samples,
   new generations and recovery after missing assets silently baseline. Keep only the last
   clip-time second of catch-up. Bound traversed cycles and emitted events using existing
   limits; atomically discard over-budget batches. Exclude the left endpoint, include the
   right endpoint, and honor duration markers before ONCE resets its visible pose.
4. Retain cursors with existing weak-identity, 256-entry LRU playback instances. Repeated
   sampling consumes no interval twice, including one stack shared by GUI and hand. A
   callback exception propagates after consumption. Nested extraction consumes silently;
   control mutation or retirement during a callback stops delivery of the remaining batch.
5. Add tests of actual item extraction with a real model registry/runtime and controlled
   clock, covering endpoint behavior, copies, control changes, fallback/reload/recovery,
   exceptions/reentrancy and bounded catch-up. Add an opt-in runnable wand counter and docs.
6. Run focused tests, root and official 26.3 checks, JAR and runnable example builds. Obtain
   independent critical review, address findings, then publish the separate branch, verify
   terminal CI and package cumulative artifacts. Do not merge, tag, release or repeat the
   graphics validation the user deferred.

## Verification boundaries

Automated runtime and compiled-consumer checks do not prove visible in-game graphics or
sound. The counter demonstrates extraction delivery, not submission/display or authority.
