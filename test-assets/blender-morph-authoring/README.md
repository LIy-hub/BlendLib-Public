# Editable morph control authoring fixture

`source.blend` is a genuine Blender 5.1.2 (`ec6e62d40fa9`) source generated by the
real registered BlendLib authoring operators. It is a static, two-bone face/body
with Blink, Smile, Breath, and Squeeze shape keys. Breath defaults to 0.15; the
other target defaults are zero. There are no Actions or animation states.

Keep `source.blend`, `surface.png`, and `detail.png` together. Open the source with
the matching add-on, then follow the [face/squeeze walkthrough](../../docs/blender-morph-editor-walkthrough.md).
Textures and the export root use portable paths relative to the source `.blend`.

Rebuild and verify from the repository root:

```sh
blender --background --python-exit-code 1 \
  --python blender-addon/scripts/verify_morph_editor.py -- --project-root .
```

- `source.blend`: editable source with four controls already applied to its
  `BlendLib.runtime.json` Text and no active draft
- `runtime-authoring.json`: the canonical manual-only source Text
- `exported/`: strict CPU-profile GLB, format-2 descriptor, and two PNG textures
- `verification.json`: actual toolchain identity, passed operator contracts, and
  exported resource SHA-256 hashes

The verifier covers Create/Add/Edit, Discard, conflicting Text selection/content,
duplicate and invalid controls, nonzero default preservation, scene identity and
profile fences, Edit Mode, the registered undo/redo invalidation handler, full
export, ignored unapplied drafts, save/reopen, and byte-identical repeated exports.
It separately loads the existing animated CPU fixture and proves that editing a
morph control preserves states, marker events, sockets, and locomotion rules.

Only resource bytes are reproducibility-checked; Blender source-file bytes may
vary between saves. This is headless operator/export evidence, not interactive
sidebar visual QA or native Minecraft renderer acceptance. To restore the supplied
example after following the editing steps, rerun the verifier.
