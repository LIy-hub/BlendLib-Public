# Blender socket editor roundtrip fixtures

These are genuine Blender 5.1.2 (`ec6e62d40fa9`) source files and strict exports, generated by:

```sh
blender --background --python blender-addon/scripts/verify_socket_editor.py -- --project-root .
```

The script starts from the checked-in `blender-authoring/source.blend` for the rigid fixture,
creates the skinned fixture from scratch, discovers paths through the actual glTF exporter,
and adds/edits sockets using the registered Blender UI operators. It checks explicit Apply,
Discard, repeat clicks, invalid/duplicate keys, Text identity/content conflicts, node rename
and reparent repair, strict duplicate object/bone names, opt-in preservation, and save/reload.
The draft cannot overwrite the saved authoring Text implicitly. Exporting an unsupported
socket offset is rejected without overwriting successful output.

- `rigid/`: Root and Pivot have nontrivial rotations and positive uniform scales. The animated
  Body owns a Grip Empty with translation, rotation, and uniform scale. The transformed Empty
  supplies the attachment offset; the socket JSON still has only `node`. Existing states,
  marker events, the Hand socket, and locomotion settings are retained
- `skinned/`: a two-bone armature with an animated Hand bone and a separate ObjectHand Empty.
  The exact joint path is discovered from the real export. Temporarily naming ObjectHand
  `Hand` verifies the strict source duplicate-name rejection; no ambiguous model is shipped
- `exported/`: existing strict-v1 GLB, descriptor, texture, and optional locomotion resources
- `expected.json`: five evaluated source-scene poses per clip, taken directly from Blender
  before export. Object world matrices use the Y-up change of basis `C M C^-1`; joint matrices
  use `C M`, matching Blender's retained bone-local axes. Expected transforms are not extracted
  from the GLB or generated by the Java implementation under test
- `verification.json`: successful operator/export checks and exported asset hashes. Two
  successive exports and a saved/reopened sidebar export must be byte-identical. Blender
  source-file bytes themselves are not used as reproducibility hashes

Run the Java roundtrip on the existing Minecraft 26.3 source set:

```sh
./gradlew -p versions/modern -Pminecraft_version=26.3 test \
  --tests '*BlenderSocketAuthoringLocomotionAcceptanceTest'
```

The five Java tests use the real `ModelAssetLoader`, `PoseSampler`, `NodePalette`, and
`SocketWorldTransform`; check translation, quaternion orientation, and uniform scale;
distinguish joint and object targets; reload independent generations; and reject unknown
paths or schema extensions. They do not change the schema or runtime and do not claim
native renderer/visual verification. `Locomotion` in the class name also places this
acceptance test in the existing 26.3 test-source inclusion rule.
